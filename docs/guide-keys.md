## Что вообще происходит (вводная)

Каждый шлюз (OpenRouter, Groq, z.ai, Mistral, Cloudflare, NVIDIA, Google, LLM7, Zen, Ollama) — это отдельный провайдер моделей со своими правилами:

- у всех **свой формат ключа** (`gsk_…`, `sk-or-v1-…`, `mstrl_…` и т.д.);
- у всех **свои бесплатные лимиты** (запросы в минуту/сутки, нейроны, кредиты);
- у всех **своя география**: кто-то прекрасно работает с IP РФ, а кто-то отдаёт 403/451 прямо до проверки ключа.

В zagent всё это упрощено до трёх действий:

1. **Получить ключ** на сайте провайдера (инструкции ниже — раздел 5).
2. **Вставить ключ** во вкладку **«Настройки»** (или руками в `config/secrets.local.json` — раздел 8).
3. **Проверить** кнопкой **«Пинг всех»** на вкладке **«Статус»**.

Ключи хранятся только в `config/secrets.local.json` — этот файл в `.gitignore` и в репозиторий не попадает. Несколько ключей одного провайдера = несколько аккаунтов: keyring крутит их по кругу, а при 429 отправляет конкретный ключ в карантин и переключается на следующий.

> **Условные обозначения** (перевод пометок исходных материалов):
> **проверено** — живой запрос с IP РФ 07.10.2026 · **документы** — официальная документация провайдера · **сообщество** — неофициальные источники, доверять с осторожностью.

## 1. Быстрый старт (5 минут)

Самый быстрый путь получить *работающий* ответ — начать с шлюзов, которые не требуют VPN и не требуют денег. Сначала два шлюза **вообще без ключа**, потом три самых простых с ключом.

### 0. Совсем без ключа (30 секунд)

**LLM7** — OpenRouter-подобный агрегатор, анонимный доступ работает (проверено):

```bash
curl https://api.llm7.io/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"GLM-5.3-Flash","messages":[{"role":"user","content":"hi"}]}'
```

**OpenCode Zen** — стабильно без ключа отвечает модель `space-bunny-free` (проверено, `cost: "0"`):

```bash
curl https://opencode.ai/zen/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"space-bunny-free","messages":[{"role":"user","content":"hi"}]}'
```

В zagent эти шлюзы уже заведены (`llm7`, `zen`) — ключи вставлять не нужно, они работают сразу.

### Шаг 1. Z.ai / GLM (2 минуты)

1. Регистрация: <https://z.ai> — email, карта не нужна.
2. Открыть <https://z.ai/manage-apikey/apikey-list> → кнопка **«Create API Key»**.
3. **Скопировать ключ сразу** — он показывается один раз. Формат: `<id>.<secret>` одной строкой, например `ВАШ_32_HEX_ID.ВАШ_SECRET`.
4. Во вкладке **«Настройки»** → секция **«Ключи шлюзов»** → выбрать `Z.ai / GLM` → вставить ключ в поле → **«Добавить»**.
5. Вкладка **«Статус»** → **«Пинг всех»** → должно быть 200 OK.

### Шаг 2. Mistral (2 минуты)

1. Регистрация: <https://auth.mistral.ai/self-service/registration> (email / Google / GitHub).
2. Ключи: <https://console.mistral.ai/api-keys/> → **«Create new key»**. Формат `mstrl_ВАШ_КЛЮЧ`.
3. Вставить во вкладку «Настройки» → «Ключи шлюзов» → `Mistral La Plateforme` → **«Добавить»**.
4. «Пинг всех» на вкладке «Статус».

### Шаг 3. Cloudflare Workers AI (3 минуты — тут два секрета, см. [раздел 5.3](#53-cloudflare-workers-ai))

1. Регистрация: <https://dash.cloudflare.com/sign-up> (email, без карты).
2. Получить **Account ID** и **API Token** (шаблон «Workers AI API Token», не Global API Key!).
3. Вставить токен в поле ключей, Account ID — в отдельное поле **«Account ID»** рядом с кнопкой **«Сохранить»**.
4. «Пинг всех».

После этих трёх шагов у вас три независимых шлюза, работающих из РФ без VPN, плюс два keyless — на этом базовый запас уже есть.

### Что выбрать под задачу

| Ваша ситуация | Что подключать в первую очередь |
|---|---|
| «Просто хочу, чтобы агент отвечал» | `llm7` + `zen` (без ключа) + `z_ai` |
| «Нужен код и рассуждения» | `groq` (gpt-oss), `cloudflare` (gpt-oss-120b), `mistralai` (codestral) |
| «Долгие контексты и консультации» | `google` (gemini-3.8-flash, под VPN), `z_ai` |
| «Есть VPN и хочется максимума моделей» | `openrouter` (`:free`-фильтр) + `nvidia` |
| «Полная автономия, без интернета» | `ollama` + локальные модели |

Оптимальная стартовая конфигурация: **5–6 ключей у разных провайдеров**. Это даёт одновременно и запас на отказ одного шлюза, и суммарную квоту, которой хватает на суточную работу агента.

## 2. Общая схема получения ключа

У 90% провайдеров путь один и тот же. Держите его в голове — дальше каждый раздел просто уточняет ссылки и нюансы.

1. **Регистрация.** Открыть сайт провайдера, указать email (или войти через Google/GitHub). Карту почти нигде не просят — во всех шлюзах из этого гайда free-план работает без неё.
2. **Консоль / дашборд.** После входа перейти в раздел развёрнутых словами: «API Keys», «Manage API key», «Settings → API tokens». Прямые ссылки — в разделе 5.
3. **Create / Generate.** Нажать кнопку создания («Create API Key», «Create new key», «Get API Key», «Create Token»). Обычно спрашивают только имя ключа.
4. **Скопировать сразу.** Ключ показывается **один раз** — при закрытии окна он превращается в маску. Если не скопировали: не страшно, удалите и создайте новый, это бесплатно и занимает 10 секунд.
5. **Вставить в zagent.** Вкладка «Настройки» → «Ключи шлюзов» → выбрать шлюз → вставить (можно несколько ключей, по одному в строке) → «Добавить».
6. **Проверить.** Вкладка «Статус» → «Пинг всех». Зелёный 200 — ключ жив.

**Правило формата.** Ключ — это одна непрерывная строка без пробелов и кавычек. Начало строки почти всегда маркирует провайдера:

| Провайдер | Начало ключа | Пример-заглушка |
|---|---|---|
| Groq | `gsk_` | `gsk_ВАШ_КЛЮЧ` |
| OpenRouter | `sk-or-v1-` | `sk-or-v1-ВАШ_КЛЮЧ` |
| Mistral | `mstrl_` | `mstrl_ВАШ_КЛЮЧ` |
| Cloudflare (токен) | `cfut_` | `cfut_ВАШ_КЛЮЧ` |
| NVIDIA | `nvapi-` | `nvapi-ВАШ_КЛЮЧ` |
| Google | `AQ.` (новый формат) | `AQ.ВАШ_КЛЮЧ` |
| Z.ai | hex-точка-secret | `ВАШ_ID.ВАШ_SECRET` |
| Zen | формат не документирован | `ВАШ_ZEN_КЛЮЧ` |

### Типичные ошибки при копировании ключа

- **Обрезанная строка.** В окне показа ключ часто длиннее экрана — «скопировал» на самом деле означает «скопировал видимую часть». Сравните длину с тем, что в консоли.
- **Лишние символы.** Кавычки, пробелы в начале/конце, перенос строки — всё это ломает `Authorization`. Вставляйте «как есть».
- **Ключ из другого раздела.** В Cloudflare рядом лежат Global API Key, R2 S3-ключи и Account ID — для zagent нужен именно **API Token** шаблона Workers AI.
- **Несколько ключей в одной строке.** Разделяйте только переводом строки, иначе получится один невалидный «суперключ».
- **Смешение форматов провайдеров.** `gsk_…` в поле OpenRouter не сработает — каждый шлюз ждёт свой формат (таблица выше).

## 3. Гео-доступность: кто работает из РФ

Сводная таблица по результатам firsthand-проверок с IP РФ без VPN, 07.10.2026 (источник: `update/Api-guide.txt`).

| Шлюз | Geo | Статус ключа | Формат ключа | Проверено |
|---|---|---|---|---|
| `z_ai` (Z.ai / GLM) | **ok** | 200 OK | `<id>.<secret>` | проверено, 200 OK на `glm-4.5-flash` |
| `mistralai` | **ok** | 200 OK | `mstrl_…` | проверено, 200 OK на `ministral-3b` |
| `cloudflare` | **ok** | 200 OK | `cfut_…` + Account ID | проверено, 200 OK на `@cf` gpt-oss-20b |
| `llm7` | **ok** | 200 OK **без ключа** | не нужен | проверено, анонимный POST |
| `zen` | **ok** | 200 OK **без ключа** | не нужен (только `space-bunny-free`) | проверено, `cost:"0"` |
| `groq` | **unstable** | то 200, то 403 | `gsk_…` | 403 10.07.2026, geo-проба 06.10.2026 — ok |
| `openrouter` | **vpn-only** | 403 security policy | `sk-or-v1-…` | проверено: 403 даже с валидным ключом |
| `nvidia` | **vpn-only** | 451 legal block | `nvapi-…` | проверено: HTTP 451 на `/v1/models` |
| `google` | **vpn-only** | 400 User location | `AQ.…` (новый формат) | проверено 07.10.2026: ключ валиден, но 400 |
| `ollama` | локально | не нужен | `http://localhost:11434` | локальный рантайм, geo не применим |

### Что значат статусы

- **ok** — работает с IP РФ напрямую, VPN не нужен. Это ваш основной резерв.
- **unstable** — то работает, то 403; зависит от подсети и времени суток. Ключ валиден, просто провайдер режет часть диапазонов.
- **vpn-only** — гео-блок: нужен VPN (обычно любая страна ЕС/США). Ключ при этом может быть полностью рабочим.
- **blocked** — недоступно даже через обычные VPN-локации (прокси с «грязных» IP тоже часто попадают в эту категорию).

## 4. Нужен ли VPN

### Заблокировано для РФ напрямую

| Шлюз | Что происходит | Нужно |
|---|---|---|
| **OpenRouter** | Их WAF отдаёт `403 Access denied by security policy` **до проверки ключа** — даже на `/models` | VPN (ЕС/США) |
| **NVIDIA NIM** | `451 Unavailable For Legal Reasons` — юридический геоблок региона | VPN |
| **Google AI Studio** | `400 User location is not supported for the API use` — ключ валиден, но запрос не пройдёт | VPN |

### Нестабилен

- **Groq** — блок подсетей/времени: с одного IP 403, через день с другого IP 200. Лечится сменой IP/VPN и повтором.

### Способ проверки: это гео или сломанный ключ

Главное правило: **403 «security policy» и 451 — это про географию, а не про ключ. Не удаляйте ключ, не помечайте его невалидным, не пересоздавайте аккаунт.**

Порядок диагностики:

1. **Без ключа** сделать `GET {base_url}/models` (или curl с фиктивным `Bearer`).
   - Ответ `403 security policy` / `451` / `400 User location` **и без ключа** → это гео. Ключ ни при чём.
   - Ответ `401` → проблема в ключе или в формате запроса.
2. **Проверить ключ «без траты квоты»**: `GET {base_url}/models` с настоящим `Authorization` — `200` означает, что ключ жив. Для OpenRouter/NVIDIA так проверять получится **только с VPN-IP**.
3. **Сменить IP** (включить VPN на любую страну ЕС/США) и повторить запрос. Прошло → гео подтверждено, ключ цел.
4. Ключ оставить в `secrets.local.json` на месте. Как только появится VPN-окно, шлюз заработает сам.

Аналогично для Groq: 403 сегодня ≠ мёртвый ключ. Повторите завтра или с другого IP, прежде чем удалять.

### Как быстро проверить свой IP

Перед тем как ругать провайдера, убедитесь, каким IP вы реально ходите:

1. Откройте <https://ifconfig.me> (или `curl https://ifconfig.me/ip`) — покажет внешний IP.
2. Включите VPN на любую страну ЕС/США и обновите страницу — IP должен смениться.
3. Повторите проблемный curl. Прошло? Значит, диагноз «гео» подтверждён, ключ рабочий.
4. Выключили VPN — часть шлюзов снова станет 403/451. Это норма: работайте с «белыми» шлюзами напрямую, а «серые» оставьте на VPN-окно.

**Важно:** бесплатные VPN-подсети часто сами в блок-листах (это и есть статус `blocked`). Если с VPN стало *хуже* — попробуйте другую локацию или другого провайдера VPN, а не удаляйте ключ.

### Шлюзы, которые НЕ требуют VPN при любых обстоятельствах

`z_ai`, `mistralai`, `cloudflare`, `llm7`, `zen`, `ollama`. Даже если интернет упал или VPN отвалился, агент продолжает работать на этой связке — именно поэтому их рекомендуют собрать первыми в разделе 1.

## 5. Пошаговые инструкции по каждому шлюзу

### 5.1 Z.ai / GLM — geo: ok

- **Регистрация:** <https://z.ai> — email, без карты.
- **Консоль ключей:** <https://z.ai/manage-apikey/apikey-list> → кнопка **«Create API Key»**. Ключ показывается **один раз** — копировать сразу.
- **Endpoint:** `https://api.z.ai/api/paas/v4/chat/completions`
- **Формат ключа:** `<32-hex-id>.<16+-secret>` — одна строка `id.secret`, точка между частями обязательна.
- **Free-модели:** `glm-4.7-flash`, `glm-4.5-flash`, `glm-4.6v-flash` (vision). Flash-линейка бесплатна **бессрочно** — во всех колонках прайса $0 (документы + notes проекта).
- **Лимиты free:** точные не опубликованы, concurrency ~5 (сообщество).
- **Типичные ошибки:**
  - пустой `text` при малом `max_tokens` — ответ ушёл в отдельное поле `reasoning_content`, поднять `max_tokens`;
  - `429` на `glm-4.6` / `glm-5` — это платные модели, а на балансе 0.
- **Не путать:** китайский `open.bigmodel.cn` — **другой** аккаунт и другой endpoint, международные ключи туда не подходят.

```bash
curl https://api.z.ai/api/paas/v4/chat/completions \
  -H "Authorization: Bearer ВАШ_ID.ВАШ_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"model":"glm-4.5-flash","messages":[{"role":"user","content":"hi"}]}'
```

### 5.2 Mistral La Plateforme — geo: ok

- **Регистрация:** <https://auth.mistral.ai/self-service/registration>, далее консоль <https://console.mistral.ai> (email / Google / GitHub).
- **Ключи:** <https://console.mistral.ai/api-keys/> → **«Create new key»**.
- **Endpoint:** `https://api.mistral.ai/v1/chat/completions`
- **Формат ключа:** `mstrl_ВАШ_КЛЮЧ`.
- **Free tier («Experiment»):** ~$10 кредитов в месяц, ~1 RPS, без карты (документы + сообщество). Кредиты начисляются помесячно, неиспользованные **не переносятся** (сообщество).
- **Free-модели:** `ministral-3b-latest`, `ministral-8b-latest`, `codestral-latest`, `open-mistral-*`.
- **Типичные ошибки:**
  - `401` с текстом «This is a paid model» — модель недоступна на Experiment-плане, а **не битый ключ**;
  - промпты по умолчанию могут идти в обучение: console → **Settings → «Allow data training»** — выключить (документы).

```bash
curl https://api.mistral.ai/v1/chat/completions \
  -H "Authorization: Bearer mstrl_ВАШ_КЛЮЧ" \
  -H "Content-Type: application/json" \
  -d '{"model":"ministral-3b-latest","messages":[{"role":"user","content":"hi"}]}'
```

### 5.3 Cloudflare Workers AI — geo: ok

У Cloudflare **два обязательных секрета**, и это самая частая ошибка новичка: без Account ID запрос уйдёт в никуда, а с Global API Key — вообще не тот ключ.

**Секрет A — Account ID**

1. Зарегистрироваться: <https://dash.cloudflare.com/sign-up> (email, без карты).
2. Найти Account ID одним из способов:
   - дашборд → **Workers AI** → **Use REST API** (ID виден прямо на странице);
   - или любой домен в аккаунте → справа панель **Overview** → Account ID внизу.
3. ID вида 32 hex-символа, без префиксов.

**Секрет B — API Token**

1. Открыть <https://dash.cloudflare.com/profile/api-tokens>.
2. **«Create Token»** → выбрать шаблон **«Workers AI API Token»** (права `Workers AI:Read` + `Workers AI:Edit`).
3. ⚠️ **НЕ «Global API Key»**, **НЕ R2/S3-ключи** — это другие учётные данные, zagent их не примет.
4. Токен нового формата начинается с `cfut_…` (проверено). Показывается один раз — копировать сразу.

**Параметры**

- **Endpoint (OpenAI-совместимый):**
  `https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/v1/chat/completions`
- **Формат ключа:** `cfut_ВАШ_КЛЮЧ` + Account ID отдельным полем.
- **Free:** 10 000 neurons/день, сброс в 00:00 UTC. При исчерпании запрос **падает** — биллинга нет (документы + notes проекта).
- **Free-модели:** `@cf/openai/gpt-oss-120b`, `@cf/openai/gpt-oss-20b`, `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, `@cf/qwen/qwen3-30b-a3b-fp8` и др.
- **Типичные ошибки:**
  - `403` на `@cf/zai-org/glm-5.3-flash` и подобных — это **paid-only** модели, на free-аккаунте они не работают (без биллинга не использовать);
  - пустой/обрезанный ответ у reasoning-моделей — нужен запас `max_tokens`.

**Вставка в zagent:** в секции «Ключи шлюзов» выберите `Cloudflare Workers AI`, в поле текстареа вставьте токен, а Account ID — в отдельное поле **«Account ID»** с кнопкой **«Сохранить»**.

```bash
curl "https://api.cloudflare.com/client/v4/accounts/ВАШ_ACCOUNT_ID/ai/v1/chat/completions" \
  -H "Authorization: Bearer cfut_ВАШ_КЛЮЧ" \
  -H "Content-Type: application/json" \
  -d '{"model":"@cf/openai/gpt-oss-20b","messages":[{"role":"user","content":"hi"}]}'
```

### 5.4 Groq — geo: unstable

- **Регистрация:** <https://console.groq.com> (Google / GitHub / email, без карты).
- **Ключи:** <https://console.groq.com/keys> → **«Create API Key»**.

## 6. Мультиаккаунты: несколько ключей одного провайдера

### Зачем

Бесплатные лимиты почти всегда **привязаны к аккаунту, а не к IP**: у OpenRouter 50 запросов в сутки на аккаунт, у NVIDIA 40 RPM на аккаунт, у Google Flash ~1500 RPD на аккаунт. Два аккаунта = вдвое больше работы. Девять аккаунтов OpenRouter = в девять раз больше суточной квоты.

### Как вставить разом

1. Вкладка **«Настройки»** → секция **«Ключи шлюзов»**.
2. Выберите шлюз в выпадающем списке.
3. В поле-текстарее **вставьте сразу несколько ключей — по одному в строке**:

```
gsk_ВАШ_КЛЮЧ_1
gsk_ВАШ_КЛЮЧ_2
gsk_ВАШ_КЛЮЧ_3
```

4. Кнопки:
   - **«Добавить»** — дописать вставленные ключи к уже сохранённым;
   - **«Заменить всё»** — стереть старые ключи шлюза и записать только вставленные;
   - **«Удалить вставленные»** — убрать из списка те ключи, которые сейчас в поле (удобно, чтобы вычистить один мёртвый аккаунт из списка).
5. Для **Cloudflare** дополнительно заполните поле **«Account ID»** → **«Сохранить»**.
6. Проверка — **«Пинг всех»** на вкладке **«Статус»**. Обновить список моделей — **«Обновить каталог»**.

### Как это работает под капотом

- Ключи хранятся как **список строк** в `config/secrets.local.json`: `"groq": ["gsk_…", "gsk_…"]`.
- **Ротация:** keyring крутит ключи по кругу — запросы распределяются между аккаунтами.
- **Карантин по 429:** получив `429`, конкретный ключ уходит в карантин на время из `Retry-After`, запрос уходит на следующий ключ. Когда карантин истекает — ключ возвращается в оборот.
- **Счётчики:** расход по каждому ключу отдельно (попытки, токены, хопы) — это то, что видно в статусе роя.
- **Окружение даёт всегда один ключ:** переменная `ZAGENT_<ШЛЮЗ>_API_KEY` возвращает только первый ключ списка — окружение рассчитано на CI, не на ротацию.

### Как это выглядит на практике

Типичный день с тремя ключами Groq:

1. `10:00` — агент делает запрос ключом №1, 200 OK, счётчик +1.
2. `10:12` — лимит RPM выбился: `429` → ключ №1 уходит в карантин до `Retry-After`, запрос тут же уходит ключом №2.
3. `10:13` — ключ №2 отвечает, пользователь ничего не замечает: failover произошёл в фоне.
4. `10:30` — карантин ключа №1 истёк, он возвращается в круг.
5. Суточный лимит одного аккаунта (1000 RPD у Groq) превращается в 3000 RPD на семейство — просто потому, что лимит считается на аккаунт.

Именно поэтому «Пинг всех» показывает ключи по отдельности: если один в карантине, а два других зелёные — система работает штатно.

### Честное предупреждение про ToS

**Один человек — это один аккаунт у одного провайдера.** Мультиаккаунтность «в одного» формально нарушает ToS большинства шлюзов (Google, OpenRouter, NVIDIA — особенно болезненно). Проект рассчитан на ротацию **своих** ключей **разных провайдеров**: свои аккаунты в z.ai, Mistral, Cloudflare, Groq, OpenRouter, NVIDIA, Google — и так вы получаете суммарно огромную квоту без единого нарушения. Множить аккаунты одного провайдера — ваш риск (бан, потеря доступа); ответственность несёте вы, не проект.

## 7. Добавление модели через вкладку «Настройки»

Каталог в zagent — это стартовый набор. Любую недостающую модель можно добавить руками.

Вкладка **«Настройки»** → секция **«Модели»**:

1. **Выберите шлюз** — из какого провайдера модель.
2. **«Идентификатор модели»** — точное имя, как его принимает API (например `glm-4.5-flash`, `@cf/openai/gpt-oss-20b`, `openai/gpt-oss-120b`). Имя нужно брать из документации провайдера или из `GET {base_url}/models` — выдуманные имена дают `404 model not found`.
3. **«Приоритет (тир)» 1–5:**
   - **1** — лучший: основной кандидат, сюда идут первые запросы;
   - **2–3** — рабочая середина: подключается, когда тир 1 в карантине или исчерпал квоту;
   - **4** — резерв;
   - **5** — запасная на крайний случай, когда всё остальное недоступно.
   Чем меньше число — тем «лучше» модель по вашей оценке. Failover идёт сверху вниз по тирам.
4. Кнопки **«Добавить модель»** (модель появится в списке ручных моделей шлюза ниже, у каждой строки своя кнопка **«убрать»**) и **«Удалить модель»** (убрать то, что вписано в поле).
5. Ниже — список уже добавленных ручных моделей шлюза.

**Поле `works`** в конфиге модели (и её колонка в материалах проекта): `works=true` — модель проверена боем и отвечает; `works=false` — ещё не проверена. Добавляйте новую модель с `works=false` и проверьте «Пингом», прежде чем полагаться на неё в роутинге.

### Пример: как распределить тиры

Допустим, вы добавляете четыре модели для кода. Раскладка может выглядеть так:

| Модель | Шлюз | Тир | Почему |
|---|---|---|---|
| `openai/gpt-oss-120b` | groq | 1 | самая сильная бесплатная, но geo-unstable |
| `@cf/openai/gpt-oss-120b` | cloudflare | 2 | та же модель, другой провайдер — страховка |
| `glm-4.7-flash` | z_ai | 3 | стабильна из РФ, бессрочно бесплатна |
| `ministral-3b-latest` | mistralai | 5 | слабее, но живёт всегда |

Идея простая: **тир 1 может отвалиться в любой момент** (429, гео, сбой), и агент должен без вашей помощи скатиться на 2, 3, 4, 5. Чем сильнее различаются модели по качеству, тем «толще» должен быть список на случай отказа.

Практическое правило: держите **не меньше 3 рабочих моделей в каждом из тиров 1–3** и хотя бы по одной в 4–5. Одна модель в тире 1 = единичная точка отказа.

## 8. Ручной способ: файл секретов и переменные окружения

### 8.1 `config/secrets.local.json`

Основное хранилище ключей. Формат — **объект, где значение это список строк** (список = ротация):

```json
{
  "groq": ["gsk_ВАШ_КЛЮЧ", "gsk_ВАШ_КЛЮЧ_2"],
  "openrouter": ["sk-or-v1-ВАШ_КЛЮЧ"],
  "z_ai": ["ВАШ_ID.ВАШ_SECRET"],
  "mistralai": ["mstrl_ВАШ_КЛЮЧ"],
  "cloudflare_token": ["cfut_ВАШ_КЛЮЧ"],
  "cloudflare_account_id": "ВАШ_ACCOUNT_ID",
  "nvidia": ["nvapi-ВАШ_КЛЮЧ"],
  "google": ["AQ.ВАШ_КЛЮЧ"]
}
```

**Имена ключей** — это поле `secret_key` из `config/gateways.json`: `groq`, `openrouter`, `z_ai`, `mistralai`, `cloudflare_token` (+ отдельный `cloudflare_account_id`), `nvidia`, `google`. У `llm7`, `zen` и `ollama` ключ не нужен (`secret_key: null`).

Как править руками:

1. Открыть `config/secrets.local.json` в любом редакторе (файла может не быть — просто создайте).
2. Добавить/заменить значение-список у нужного шлюза.
3. Сохранить, убедиться, что JSON валиден (запятые, кавычки).
4. Перезапустить zagent или обновить страницу UI, затем «Пинг всех».

Допустима и **строка** вместо списка (один ключ) — так было изначально; для ротации используйте список.

### 8.2 Переменные окружения

Имя переменной: **`ZAGENT_<ID шлюза>_API_KEY`**, где `<ID>` — `id` шлюза из `gateways.json` в верхнем регистре (дефисы → подчёркивания):

| Шлюз | Переменная окружения |
|---|---|
| groq | `ZAGENT_GROQ_API_KEY` |
| openrouter | `ZAGENT_OPENROUTER_API_KEY` |
| z_ai | `ZAGENT_Z_AI_API_KEY` |
| mistralai | `ZAGENT_MISTRALAI_API_KEY` |
| cloudflare | `ZAGENT_CLOUDFLARE_API_KEY` |
| nvidia | `ZAGENT_NVIDIA_API_KEY` |
| google | `ZAGENT_GOOGLE_API_KEY` |

```powershell
# PowerShell (текущая сессия)
$env:ZAGENT_GROQ_API_KEY = "gsk_ВАШ_КЛЮЧ"
python tools/cli.py
```

```bash
# Bash
export ZAGENT_GROQ_API_KEY="gsk_ВАШ_КЛЮЧ"
```

**Приоритет:** окружение → файл секретов. Важно: окружение **всегда даёт только один ключ** (первая переменная из списка) — для ротации нескольких аккаунтов используйте `secrets.local.json`.

## 9. Безопасность ключей

1. **Ключи только в `config/secrets.local.json`.** Этот файл в `.gitignore` (строка про `secrets.local.json`) и в репозиторий не попадает. Никогда не кладите ключ в код, в конфиги вроде `gateways.json`, в логи и в SSE-события.
2. **Не коммитить.** Даже один закоммиченный ключ — это чужие деньги/квота на вашем имени и повод для бана. Проверить перед коммитом:

   ```powershell
   .venv\Scripts\python.exe tools\check_secrets.py
   ```

   Скрипт делает две вещи: ищет в git-индексе строки **по образцу** ключей известных провайдеров (`gsk_`, `sk-or-v1-`, `nvapi-`, `mstrl_`, `cfut_`, z.ai `id.secret`, `AQ.` …) и **сверяет буквально** с настоящими ключами из `secrets.local.json` — так ловится ключ, спрятанный под неожиданным именем. Проверяется только индекс (`git ls-files`), поэтому незакоммиченные черновики не мешают.
3. **Не писать ключ в чат, лог, issue, отчёт стенда, скриншот.** Ключ, показанный на скриншоте или вставленный в переписку, — это уже утечка: его подхватят боты, сканирующие публичные тексты, за минуты.
4. **Ключ показывается один раз** — но «один раз» ≠ «можно показать всем». Копируйте сразу в буфер → сразу в zagent.
5. **Отзыв при подозрении.** Зашли в консоль провайдера → Revoke/Delete ключа → создали новый. Это 10 секунд и полностью закрывает инцидент.
6. **Не выкладывать `secrets.local.json`** даже «временно» в облако/архив/расшаренную папку.
7. **Разные ключи — разные аккаунты.** Не используйте один ключ на нескольких машинах «на всякий случай»: лимит общий, а в случае взлома репутация у обоих.

### Если ключ всё-таки утёк

Паниковать не нужно, действовать быстро:

1. Зайти в консоль провайдера → **Revoke / Delete** старого ключа.
2. Создать новый и вставить его в zagent («Настройки» → «Ключи шлюзов» → «Заменить всё»).
3. Удалить ключ из всех мест, куда его успели вписать: чаты, заметки, скриншоты, CI-переменные.
4. Если ключ был в git-истории — считайте его скомпрометированным даже после удаления файла: пересоздайте, а историю чистите только осознанно (`git filter-repo`) и лучше в форк.
5. Прогнать `tools/check_secrets.py` — он должен показать чисто на новых ключах.

## 10. Диагностика: код ошибки → что делать

| Код / симптом | Что это | Что делать |
|---|---|---|
| **401** Unauthorized | Ключ невалиден, урезан или скопирован не до конца; у Mistral `401 "paid model"` = модель не входит в free-план | Проверить ключ (новое окно → Copy), убедиться что строка целиком и без пробелов; для Mistral сменить модель на free |
| **402** Payment Required | У модели кончился бесплатный пул (OpenRouter) или не хватает баланса (z.ai paid-модели) | Подождать суточного сброса / выбрать `:free`-модель / не трогать paid-модели без баланса |
| **403** Forbidden | Groq: нестабильный гео-блок подсети. OpenRouter: `403 security policy` = гео (WAF до проверки ключа). Cloudflare: paid-only модель на free-аккаунте | **Ключ не удалять!** Groq — сменить IP/повторить позже. OpenRouter — включить VPN. Cloudflare — взять `@cf/...` free-модель |
| **404** model not found / `no longer available` | Модели не существует или закрыта для новых аккаунтов (Google 2.5-линейка) | Уточнить имя через `GET {base_url}/models`; для Google использовать `gemini-3.8-flash` |
| **400** «User location is not supported for the API use» | Google: гео-блок РФ. **Ключ валиден** | Включить VPN (ЕС/США) и повторить. Ключ не трогать |
| **429** Too Many Requests | Лимит RPM/RPD/TPM исчерпан | Соблюдать `Retry-After`; у Groq смотреть заголовки `x-ratelimit-*`. В zagent: keyring сам карантинит ключ и берёт следующий |
| **451** Unavailable For Legal Reasons | NVIDIA: юридический геоблок региона | VPN. Ключ не удалять и не пересоздавать |
| **5xx** (500/502/503/504) | Сторонний сбой провайдера (у NVIDIA встречаются 500) | Повторить через несколько секунд, переключиться на другой шлюз — это не ваша ошибка |
| **Пустой `text` при reasoning-модели** (gpt-oss, GLM, DeepSeek, Nemotron) | Весь `max_tokens` съел `reasoning_content`, сам ответ обрезан | Ставить `max_tokens >= 2000` и/или увеличить запас; ответ читать в поле `reasoning_content` |
| **403 FreeTierError** (Zen) | Модель `-free` работает только внутри родного OpenCode (проверка origin) | Использовать `space-bunny-free` или платный аккаунт |
| **«Ключи не заданы»** | Нет `secrets.local.json` или нет переменной окружения | Создать файл (раздел 8) или задать `ZAGENT_<ID>_API_KEY` |
| **Пустой ответ / таймаут на Groq-403** | Гео, см. 403 | Сменить IP, не удалять ключ |

**Быстрая проверка без траты квоты:**

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer ВАШ_КЛЮЧ" \
  https://api.groq.com/openai/v1/models
# 200 — ключ жив; 401 — ключ; 403/451 — гео
```

### Порядок действий, если всё пало сразу

1. **Не паниковать и не удалять ключи.** Синхронный отказ нескольких шлюзов почти всегда = ваш IP попал в общий бан (429) или VPN отвалился.
2. Зайти на вкладку **«Статус»** и посмотреть, кто в карантине, а кто отвечает.
3. Если карантин везде — дождаться `Retry-After` (у Groq лимиты сбрасываются посуточно, у Google ~полночь PT).
4. Если гео-ошибки везде — проверить IP (раздел 4), включить/выключить VPN.
5. Подстраховаться локально: `ollama pull qwen3:8b` и включить шлюз `ollama` — ответы агента не встанут полностью.
6. После восстановления — «Пинг всех» и «Обновить каталог», чтобы вернуть карантинные ключи в оборот.

## 12. FAQ

**1. Ключ не скопировал, окно закрылось — он потерян навсегда?**
Нет. Ключ — не хрупкий ресурс: зайдите в консоль провайдера, удалите старый и создайте новый. Бесплатно, 10 секунд. Скорее всего там же лежит список уже созданных ключей, и старый можно просто пересоздать.

**2. Чем «Пинг всех» отличается от curl-проверки?**
«Пинг всех» (вкладка «Статус») проверяет все шлюзы сразу через инфраструктуру проекта и показывает карантин/ошибки. curl из раздела 5 — точечная проверка одного шлюза без затрагивания остальных. Имейте в виду: пинг всего реестра жжёт квоту, поэтому для тонкой диагностики лучше curl на конкретный endpoint.

**3. Получилось 403/451/400 User location. Удалять ключ?**
**Нет.** В 90% случаев это гео, а не ключ: WAF OpenRouter и NVIDIA отвечают до проверки ключа, Google просто не пускает РФ-IP. Ключ валиден — оставьте его, включите VPN (или подождите смены IP у Groq) и повторите.

**4. Можно ли вставить 5 ключей одного шлюза?**
Можно — технически да: поле-текстареа принимает сколько угодно строк, keyring будет крутить их по кругу. Но помните про ToS (раздел 6): 5 аккаунтов одного провайдера «в одного» — нарушение. Легальный эквивалент — аккаунты в 7 разных провайдерах, и суммарной квоты хватит с запасом.

**5. Какой шлюз выбрать первым вообще?**
`llm7` или `zen` — работают без ключа прямо сейчас. Дальше z.ai (бессрочные бесплатные Flash-модели), Mistral ($10/мес кредитов), Cloudflare (10K нейронов/день). Groq добавить как «нестабильно, но быстрый», OpenRouter/NVIDIA/Google — когда будет VPN.

**6. Модель отвечает пустым текстом, но ошибок нет. Почему?**
Это reasoning-модели (gpt-oss, GLM, DeepSeek, Nemotron): при маленьком `max_tokens` весь бюджет съедает размышление, а сам ответ обрезается до пустоты. Ставьте `max_tokens >= 2000` — либо смотрите поле `reasoning_content`.

**7. Сколько стоят все эти шлюзы?**
Ноль. Во всех перечисленных есть free-план без карты: z.ai Flash — бесплатно бессрочно, Mistral ~$10/мес кредитов, Cloudflare 10 000 нейронов/день, Groq ~30 RPM, OpenRouter free-модели, NVIDIA 40 RPM, Google Flash ~1500 RPD, LLM7/Zen/Ollama — вообще без ключа. Платные опции (баланс z.ai, пополнение Zen от $20) нужны только если захотите тяжёлые модели.

**8. Как добавить модель, которой нет в списке?**
Вкладка «Настройки» → секция «Модели» → выбрать шлюз → вписать точный `Идентификатор модели` → выбрать тир 1–5 → «Добавить модель». Проверить — «Пинг всех» на «Статусе». Если пинг зелёный, у модели можно поднять `works`.
