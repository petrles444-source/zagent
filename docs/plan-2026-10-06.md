## Диагностика живого прогона (задача 64/65)

Причины «читал файлы до смерти бюджета и не выдал отчёта»:

1. **Обрезка содержимого без подсказки.** `_tool_result_brief` показывает первые
   4000 символов файла и молчит, что остальное можно взять через `offset`.
   Файл `hub/agent.py` — 1663 строки; модель видит ~80 строк, перечитывает с
   тем же `offset=0`, получает те же строки → цикл до `max_steps`.
2. **Бюджет только предупреждает.** `token_budget` пишет warning в события, но
   не останавливает чтение и не требует отчёт. Модель продолжает тот же цикл.
3. **Нет гарантии ответа.** При исчерпании шагов `finished=False` → `FAILED`
   без единого слова по делу. Пользователь получает «сбой».
4. **Нет встроенного порядка работы для большой задачи.** Под капотом нет
   инструкции «сначала составь список файлов, обойди по очереди, не
   перечитывай, в конце отдай JSON».

## Про мусор в корне: важная оговорка

Папки `tmpXXXXXXXX` в корне выглядят как вина тестов, и частично это так:
в `tests/test_audit_round3.py` был помощник `tempfile_root()` на
`mkdtemp()` без уборки — он создавал папку на каждый прогон и никогда её не
удалял. Исправлено на `tmp_path`.

Но основная причина — не тесты. `tempfile.gettempdir()` на этой машине
возвращает рабочую папку проекта, потому что `%TEMP%`
(`C:\Users\HP\AppData\Local\Temp`) недоступен для записи из процесса
Python: `PermissionError`. Python молча перебирает всех кандидатов и,
не найдя доступного, берёт текущую папку. Из-за этого `pytest-of-HP` и
`tempfile.mkdtemp()` в `bench/sandbox.py` тоже писали в корень.

Это ограничение окружения, а не дефект zagent: PowerShell в ту же папку
пишет без вопросов. Обходной путь (`conftest.py`, переопределяющий
`tempfile.tempdir`) в проект не добавлен — он лечил бы чужую проблему и
мешал бы на нормальной машине. Правила `tmp*/` в `.gitignore` остаются
как страховка.
