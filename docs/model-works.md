# Кто из моделей работает агентом

Замер 06.10.2026, шлюзы NVIDIA, Groq, OpenRouter.

## Что это проверяет и почему не пинг

Пинг спрашивает «отвечает ли модель». Это не тот вопрос, который стоит перед
агентом. Агенту нужно: получив задачу и каталог из шести инструментов, **сам
дойти до вызова**, создать файл и сказать об этом.

Проверка «умеет ли печатать JSON нужного формата» (`tools/check_tool_models.py`)
к этому не подходит: между «печатает JSON» и «делает» расстояние огромное.
Поэтому здесь настоящий агент, настоящий Guard и настоящая папка, а вердикт
ставится по файлу на диске.

**Почему не по ответу модели.** Сказать «готово» можно и ничего не сделав —
и это самый убедительный способ испортить такой замер. Файл либо есть и
содержит ожидаемое, либо нет.

**Почему папка у каждой своя.** Иначе первая модель создаст файл, а остальные
получат «готово» просто потому, что файл уже на месте.

**Почему причины разделены.** «Не сделала из-за лимита аккаунта» и «не умеет
вызывать инструмент» — разные вещи. Первое пройдёт само через минуту, второе
надо убирать из ротации. Свести их к «модель плохая» нельзя: из такого вывода
следует вывод, которого не делали.

Задача: `Создай файл hello.txt в текущей папке с единственной строкой: Привет`

Измерено 25 моделей, выполнили 17.

Повторить:

```bash
python tools\check_agent_works.py --gateways nvidia,groq,openrouter \
                                  --json tmp\agent_works.json \
                                  --markdown docs\model-works.md
```

## Что из этого следует

**Быстро — не значит хорошо, но часто связано.** Первые шесть моделей уложились
меньше чем в четыре секунды, и все справились. Медленная `llama-3.2-90b-vision`
справилась за 31.6 с — зря: у неё есть `nemotron-3-super` вдвое быстрее.

**NVIDIA оказался самым быстрым шлюзом**, хотя у него всего четыре аккаунта по
40 запросов в минуту. Считать надо по измеренному времени задачи, а не по
числу моделей в каталоге.

**Одна и та же модель на разных шлюзах — разное время.** `nemotron-3-super-120b`
на NVIDIA отвечает за 1.8 с, на OpenRouter — за 2.0 с, а `nemotron-3-ultra-550b`
на OpenRouter — уже за 3.6 с при вчетверо большем ранге. Ранг из `tiers.json`
про размер модели ничего не говорит.

**Groq — самый быстрый, но один из двух его моделей не работает.**
`gpt-oss-20b` помечена `tools: false`: провайдер вернул «Tool choice is none,
but model called a tool» — модель хотела вызвать инструмент, хотя вызов был
запрещён. Это свойство модели, а не временная беда, и лечится только заменой.

**`openrouter/openrouter/free` — маршрутизатор провайдера.** Конкретная модель
неизвестна заранее, поэтому время и качество гуляют от прогона к прогону.

## Оговорки к замеру

Задача маленькая — один файл, три-четыре шага. Это сделано намеренно: задача на
двадцать шагов измеряет не модель, а терпение, и сравнение становится
бессмысленным. Но и обратного утверждения замер не даёт: «выполнила задачу из
одного шага» не значит «справится с многостраничным сайтом».

Время в таблице — это полный цикл агента: три запроса к модели плюс создание
файла. Оно зависит от задержки первого запроса на конкретном шлюзе в конкретный
момент, поэтому между прогонами расходится в разы. Для сравнения моделей это
пригодно, для сравнения замеров одного шлюза — нет.

Модели с пометкой «лимит у аккаунта» стоит перепроверить позже: на момент
прогона аккаунты OpenRouter были выбраны. Их результат ничего не говорит о
самой модели.
