# zagent

Локальный агентный рантайм на бесплатных LLM. Три слоя:

1. **Реестр моделей** — находит все модели, отвечающие через API без оплаты,
   пингует их, показывает статус, генерирует конфиги для других инструментов.
2. **Агент** — работает с файлами (создание, правка, удаление), с уровнями
   доступа и режимами автономии, сам переключает модель при отказе.
3. **Веб-интерфейс** — таблица статусов с кнопкой пинга, проверка адекватности
   моделей, запуск агента, скриншоты для vision-моделей.

Ключевая идея: **39 бесплатных моделей, 8 шлюзов, один агент.** Он берёт лучшую
доступную модель по приоритету, а когда та упирается в лимит — молча
переключается на следующую. Карантины накапливаются, поэтому агент не ломится
в модель, которая только что отдала 429.

## Оформление

Пять тем переключаются точками в верхней панели:

| Тема | Когда нужна |
|---|---|
| **тёмная** | обычная работа вечером |
| **чёрная** | OLED: края панелей совпадают с фоном окна |
| **светлая** | днём, при ярком свете |
| **синяя** | холодный деловой тон |
| **серая** | максимально спокойная, без цвета |

Тема сохраняется и применяется **до первой отрисовки**, поэтому при загрузке не
моргает. При первом запуске берётся тема системы. Перехода на фоне намеренно
нет: при частой смене темы анимация не успевает завершиться, и страница
остаётся в цвете прошлой темы — выглядит как «тема не применилась».

Все цвета берутся из переменных `--bg`, `--panel`, `--text`, `--accent` и
прочих, поэтому новая тема — это ~15 строк, а не правка всего CSS. Производные
цвета (бейджи, подсветки, рамки) считаются через `color-mix` от токена статуса,
так что они следуют за темой сами.

## Доступность из России

Рядом с каждой моделью — метка: `РФ ✔` работает без VPN, `РФ 🔒` нужен VPN,
`РФ ✘` недоступна, `РФ ?` не проверено.

Проверяется в два замера, и это не формальность: **с включённым VPN отвечает
почти всё**, поэтому один такой замер не доказывает ничего. Вердикт «работает
без VPN» ставится только по замеру с выключенным VPN, и он не затирается вторым.

Во вкладке «Модели» есть две кнопки с живым прогрессом (сколько сделано,
сколько осталось, какая модель проверяется сейчас). Кнопка «Замер с VPN»
заблокирована, пока не сделан первый: без него второй бессмыслен.

Переключатель «VPN выключен — сначала модели без VPN» в вкладке «Доступ»
опускает модели, которым VPN необходим, в конец списка, но **не выбрасывает
их**: вдруг VPN включится.

Из консоли то же самое: `zagent.bat geo --direct` и `zagent.bat geo --vpn`.

## Граница воркспейса

Агент работает внутри папки воркспейса. Но граница — не стена, а замок:
когда задача требует выхода наружу, агент останавливается и спрашивает вас.

Всё зависит от выбранного уровня доступа:

| Уровень доступа | Что делает агент за пределами воркспейса |
|---|---|
| **чтение** (1) | спрашивает разрешение |
| **запись** (2) | спрашивает разрешение |
| **полный** (3) | делает сам, без вопроса |
| любой + жёсткая граница | никогда не выходит |

Полный доступ — это уже ответ на вопрос «можно ли выходить наружу», поэтому
спрашивать после его выбора было бы докучать вопросом, на который вы ответили
уровнем доступа.

Когда вопрос нужен, в интерфейсе появляется окно с путём и тремя кнопками:

| Кнопка | Что делает |
|---|---|
| **Только сейчас** | разрешает этот путь в текущей задаче |
| **Всегда разрешить** | разрешает его во всех следующих задачах |
| **Отклонить** | агент получает отказ и ищет другой способ |

Три важные детали:

- **Агент не отказывается заранее.** В системном промпте сказано: если путь
  снаружи, просто вызови инструмент — система сама покажет окно. Без этого
  модель честно говорит «не могу, файл за пределами директории» и до вопроса
  не доходит.
- **Если модель всё же отказалась словами**, система это замечает. Сначала
  она требует от модели реально вызвать инструмент (обычно хватает одного
  раза), а если модель упирается — поднимает запрос разрешения сама, взяв путь
  из текста ответа. Так окно появляется всегда, а не только когда модель
  догадается оставить вызов инструмента.
- **Отказ — это ответ, а не новый вопрос.** Агент получает явный отказ, и путь
  запоминается: второй раз по нему он не спрашивает, а ищет обходной путь.
  Иначе он ходил бы по кругу до конца шагов.

**Вопрос переживает перезапуск.** Пока вы не ответили, задача стоит в статусе
`ожидает разрешения` с сохранённым чекпоинтом. Можно закрыть программу,
открыть позже и ответить — задача продолжится с того же места.

Переключатель «мягкая / жёсткая» — во вкладке «Доступ». В жёстком режиме
агент никогда не выходит за папку, а в системном промпте прямо сказано не
пытаться.

Разрешение всегда точечное: «Всегда разрешить» на `C:\work\data` открывает
`C:\work\data\config.json`, но не `C:\work\data-secret` — пути сравниваются
по компонентам, а не по началу строки.

### Переключатель доступа работает

Настройки воркспейса перекрывают общие, поэтому выбор уровня доступа,
автономии, эскалации и лимита шагов применяется и к активному воркспейсу.
Иначе переключатель выглядел бы рабочим, а задачи продолжали бы выполняться
по старому уровню. В состоянии отдаётся действующее значение, а не только
общее, — переключатель всегда показывает то, что реально применяется.

## Запуск

### Основной способ: двойной клик по `zagent.bat`

`zagent.bat` сам создаст `.venv`, поставит зависимости, проверит ключи, запустит
агента с веб-панелью и откроет браузер на `http://127.0.0.1:8783`.

Один файл на всё. Команды передаются аргументами:

```cmd
zagent.bat                          панель агента (то же, что двойной клик)
zagent.bat check                    проверить окружение
zagent.bat modes                    список моделей с приоритетами
zagent.bat ping                     пинговать всё и записать отчёт
zagent.bat sanity                   проверить адекватность моделей
zagent.bat ask "вопрос"            спросить модель через failover
zagent.bat consult "вопрос" -n 3   спросить 3 модели и сравнить
zagent.bat agent "задача"           задача агенту из консоли
zagent.bat agent --access 3 "удали tmp.txt"
zagent.bat connect                  инструкции по подключению ко всему софту
zagent.bat connect opencode         инструкция только для OpenCode
zagent.bat export opencode          готовый конфиг в stdout
zagent.bat ws list                  список воркспейсов
zagent.bat ws add C:\work           добавить папку для агента
zagent.bat ws use work              переключиться на воркспейс
zagent.bat test                     прогнать тесты
zagent.bat bench                    список заданий стенда
zagent.bat bench run all --dry      проверить стенд без моделей
zagent.bat help                     полный список
```

Чтобы закрепить за файлом: правый клик → «Открыть с помощью» → `zagent.bat`.

### Без bat-файла

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy config\secrets.local.json.example config\secrets.local.json

python tools\serve.py                        # панель агента
python tools\agent.py --access 2 run "задача"  # агент из консоли
python tools\cli.py ping --write              # каталог моделей
```

## Требования

- Python 3.11+ (проверено на 3.14.7)
- Обязательно: `httpx`
- Для скриншотов: `Pillow`
- Для встроенного браузера: `playwright` + `python -m playwright install chromium`
- Для тестов: `pytest`

## Ключи

Ключи лежат в `config/secrets.local.json`, который в `.gitignore`. Файл создаётся
из шаблона:

```bash
copy config\secrets.local.json.example config\secrets.local.json
```

```json
{
  "openrouter": "sk-or-v1-...",
  "mistralai": "mstrl_...",
  "z_ai": "<id>.<secret>",
  "groq": "gsk_...",
  "cloudflare_token": "cfut_...",
  "cloudflare_account_id": "51c12f..."
}
```

Любой ключ можно задать переменной окружения — она имеет приоритет над файлом.
Имя: `ZAGENT_<ID>_API_KEY`, где `<ID>` — id шлюза в верхнем регистре.
Например, `ZAGENT_OPENROUTER_API_KEY`, `ZAGENT_Z_AI_API_KEY`.

**Ключи в экспортируемые конфиги не попадают** — вместо них подставляются имена
переменных окружения.

### Нюансы провайдеров

| Шлюз | Что нужно |
|---|---|
| Cloudflare Workers AI | Именно **API Token** (`cfut_...`), а не Access Key ID / Secret Access Key из R2. Их в Workers AI не принимает. |
| Ollama (локально) | Ключ игнорируется, в конфиге стоит литерал `ollama`. |
| llm7.io, OpenCode Zen | Ключ не нужен вообще. |

## Агент

```bash
# общие параметры
python tools\agent.py --help

--access 1|2|3         1=чтение, 2=чтение и запись, 3=полный доступ
--autonomy yolo|normal|strict|plan
                       yolo   — решает сам
                       normal — спрашивает перед рискованным
                       strict — спрашивает перед каждой правкой
                       plan   — сначала план, ждёт одобрения
--escalation off|auto|on
                       как агент просит вас о помощи
--model gateway/model   зафиксировать модель вместо авто-выбора
--speed                быстрые модели приоритетнее
--vision               только модели, умеющие изображения

# задачи
python tools\agent.py run "задача"        # до конца
python tools\agent.py step "задача"       # один шаг
python tools\agent.py plan "задача"       # построить план
python tools\agent.py --access 3 run "удали файл x.txt"

# выбор моделей
python tools\agent.py modes               # список с тирами
python tools\agent.py ask "вопрос"        # одиночный запрос через failover
python tools\agent.py consult "вопрос" -n 3   # спросить 3 модели
python tools\agent.py sanity              # проверить адекватность всех

# инструменты напрямую
python tools\agent.py read hub/config.py
python tools\agent.py write notes.md       # содержимое из stdin
python tools\agent.py edit a.py "старое" "новое"
python tools\agent.py grep "def main" hub
python tools\agent.py shell "git status"
python tools\agent.py shot screenshots/screen.png

# браузер
python tools\agent.py fetch https://example.com --shot
python tools\agent.py login https://accounts.google.com
```

### Инструменты агента

| Инструмент | Уровень | Что делает |
|---|---|---|
| `read_file` | чтение | прочитать текстовый файл |
| `list_dir` | чтение | содержимое каталога |
| `search_text` | чтение | поиск по файлам |
| `write_file` | запись | создать или перезаписать |
| `edit_file` | запись | точечная замена строки |
| `delete_path` | **полный** | удалить файл или каталог |
| `run_shell` | **полный** | выполнить команду |
| `capture_screen` | чтение | снимок экрана |
| `image_to_data_url` | чтение | закодировать картинку для vision-модели |

Агент спрашивает вас, а не гадает, когда: строка для замены встречается
несколько раз, файл бинарный, не хватает уровня доступа, нужна авторизация.

### Как выбирается модель

Приоритет задаётся в `config/tiers.json` — от 1 (лучшие) до 5 (резерв).
Ключевые модели сейчас:

| Тир | Модели |
|---|---|
| 1 | `nemotron-3-ultra-550b` (550B MoE), `nemotron-3-super-120b`, `gpt-oss-120b` на Groq |
| 2 | `glm-4.7-flash`, `qwen3.8-27b`, `cohere/north-mini-code`, `llama-3.3-70b` на Cloudflare |
| 3 | `gemma-4-26b` (vision), `codestral`, `DeepSeek-V4-Flash` без ключа |

При отказе модель уходит в карантин: `limited` (429) — 5 минут с ростом,
`blocked` (403 провайдера) — час, `down` — 90 секунд. После успешного ответа
карантин снимается.

## Проверка адекватности

Бесплатные модели предсказуемо плохи в трёх вещах: теряют контекст, смешивают
языки, зацикливаются. `sanity` отправляет длинный протокол с кодом, спрятанным
в начале, и просит вернуть JSON с этим кодом в конце:

```
✔ not_degenerate  9 слов
✔ context         токен из контекста найден
✔ follow          JSON-инструкция выполнена
✘ language        ответ ушёл в латиницу (0% кириллицы)
✔ latency         358 мс
```

`gpt-oss-120b` на Groq набирает 0.8 — отвечает быстро и по делу, но на русском
отвечает по-английски. Для агента, который пишет код, это нормально; для
текстов — нет.

## Скриншоты и vision

Vision — вспомогательная возможность, приоритет у текста и кода. Агент сам
просит скриншот, когда не может прочитать содержимое (ошибка в GUI, нужна
веб-страница), и вы можете прислать снимок сами.

```bash
python tools\agent.py shot screenshots/screen.png
python tools\cli.py ask --file screenshots/screen.png "что здесь?"
```

Подтверждённые vision-модели: `cloudflare/@cf/google/gemma-4-26b-a4b-it`,
`z_ai/glm-4.6v-flash`, плюс помеченные в `tiers.json`. Режим `--vision`
ограничивает выбор только ими.

Требования к картинке: минимум 10×10 пикселей (проверено — меньше Cloudflare
отклоняет), до 4 МБ.

## Встроенный браузер

Настоящий Chromium через Playwright с JavaScript. Профиль в `browser-profile/`
сохраняет сессию между запусками.

```bash
.venv\Scripts\python.exe -m pip install playwright
.venv\Scripts\python.exe -m playwright install chromium

python tools\agent.py fetch https://example.com --shot
python tools\agent.py login https://github.com/login
```

**Про вход в аккаунты.** Пароль и капчу вводите вы, в открытом окне, один раз.
Дальше cookies живут в профиле и повторный логин не нужен. Антибот-проверки
Google мы не обходим — это нарушение ToS и ломается постоянно; вместо этого мы
переиспользуем сессию, поэтому проверки и не возникает. Если страница требует
авторизации, агент скажет об этом и попросит вас войти.

## Веб-интерфейс

```bash
python tools\serve.py            # http://127.0.0.1:8783
```

Браузер откроется сам. Остановить — `Ctrl+C` в окне, где запущено, или закрыть
`zagent.bat`.

Три панели на одном экране, без переключения вкладок на весь экран:

```
┌──────────────┬─────────────────────────┬──────────────────────┐
│ воркспейс    │ агент: чат / браузер /  │ файлы воркспейса     │
│ модели       │ просмотр файлов         │                      │
│ доступ       ├─────────────────────────┤                      │
│ очередь      │ вложения + поле ввода   │                      │
└──────────────┴─────────────────────────┴──────────────────────┘
       ↔                      ↔
   разделители мышью: ширину панелей можно менять как угодно
```

Левая панель — четыре вкладки:

- **Модели** — все модели с тирами, статусом, задержкой и оценкой
  адекватности. Локально видны provider id, base URL и API-ключ каждого
  шлюза, а рядом — подробные инструкции по подключению к OpenCode, Codex,
  Zed, Cline и прочему софту, без похода на сайты.
- **Доступ** — уровень доступа, режим автономии, эскалация, лимит шагов и
  переключатель границы воркспейса (мягкая / жёсткая).
- **Очередь** — задачи, их статусы и отказы моделей.
- **Проверка** — прогон sanity-пробы, видно за что модель забракована.

Центр: чат агента с живым журналом, вложения, встроенный браузер.
Справа: дерево файлов воркспейса, просмотр и редактирование.

Сделан на стандартной библиотеке: зависимость у проекта одна, и веб не должен
её ломать.

## Команды реестра

```bash
python tools/cli.py scan                   # собрать каталог (без пинга)
python tools/cli.py ping --write           # собрать + проверить живым запросом + записать отчёт
python tools/cli.py list                   # показать последний отчёт
python tools/cli.py list --only down       # только нерабочие
python tools/cli.py list --gateway groq    # только один шлюз

python tools/cli.py export opencode --verified-only   # opencode.jsonc
python tools/cli.py export codex --verified-only      # фрагмент ~/.codex/config.toml
python tools/cli.py export zed --verified-only        # Zed settings.json
python tools/cli.py export cline --verified-only      # Cline / Roo Code
python tools/cli.py export kilocode --verified-only   # Kilo Code
python tools/cli.py export plain --verified-only      # плоский список моделей

python tools/cli.py ask "задача" --gateway groq
python tools/cli.py swarm "задача" --gateway openrouter --limit 5
```

`--verified-only` исключает модели со статусом `blocked` и `down` — в конфиг
редактора попадает только то, что реально отвечает.

Пример вывода `ping`:

```
@cf/openai/gpt-oss-120b              ok       cloudflare   2.4s  tokens: 74+45
openai/gpt-oss-120b                  ok       groq         0.4s  tokens: 78+40
qwen/qwen3.8-27b                     ok       groq         0.1s  tokens: 18+2
DeepSeek-V4-Flash-0731               ok       llm7         0.3s  tokens: 90+77
glm-4.7-flash                        ok       z_ai         3.2s  tokens: 12+229 (повтор)
thinkingmachines/inkling:free        blocked  openrouter   0.3s  доступ закрыт провайдером — не использовать

Пригодных моделей: 37 из 39 (blocked: 2, limited: 5, ok: 30, slow: 2)
```

### Статусы

| Статус | Значение |
|---|---|
| `ok` | ответ получен быстрее порога |
| `slow` | ответ получен, но дольше `--slow-after` (по умолчанию 5 с) |
| `empty` | ответ без текста — reasoning-модель съела `max_tokens` |
| `limited` | HTTP 429, лимит исчерпан; модель жива, повторить позже |
| `blocked` | доступ закрыт провайдером постоянно (`403`, «only within ...») |
| `down` | сеть, 5xx или таймаут |
| `skipped` | не проверялась (модель без ключа) |

Коды возврата: `0` — есть пригодные модели, `1` — ни одной, `2` — ошибка конфигурации.

## Как добавить шлюз

Всё в `config/gateways.json`:

```jsonc
{
  "id": "example",                          // id шлюза
  "label": "Example",                       // имя в отчётах
  "base_url": "https://api.example.com/v1", // base_url (шаблон {placeholder} допустим)
  "needs_key": true,                        // false = keyless
  "free_models": ["model-a", "model-b"],    // статический список бесплатных
  "free_marker": ":free",                   // маркер бесплатности в живом каталоге
  "routers": ["example/free"],              // авто-роутеры, всегда бесплатные
  "supports_responses": true,               // есть ли /responses (нужно для Codex)
  "discover_live": false,                   // брать список из GET /models (Ollama)
  "catalog": ["static", "live"]             // необязательно: что читать
}
```

Модели попадают в реестр из трёх источников: `free_models` из конфига, живой
`GET /models` (для OpenRouter дополнительно проверяется, что цена нулевая), и
списка `routers`.

## Стенд: проверка агента

Отдельный инструмент отвечает на вопрос «стал ли агент лучше». Без него
правка промпта выглядит как правка промпта.

```bash
zagent.bat bench                  список заданий
zagent.bat bench check            проверить задания и индекс, моделей не трогая
zagent.bat bench refs             показать библиотеку эталонов
zagent.bat bench kinds            список видов проверок
zagent.bat bench run all          прогнать всё
zagent.bat bench run LANDING-001  одно задание
zagent.bat bench run all --dry    на заглушке, без сети
```

### Как это устроено

```
tasks/LANDING-001.yaml ──► песочница ──► агент ──► проверки ──► отчёт
ref/INDEX.yaml         ──► подкладывается      ▲
                          по исходным путям    │
                                           веса и штрафы
```

Задание выполняется в отдельной временной папке. Агент получает её как
`base_dir`, а `make_guard` делает её физической границей: писать за её пределами
он не может даже с полным доступом.

Эталоны кладятся **по исходным путям из индекса** (`games/snake/index.html`),
а не под другими именами. На живой модели это выяснилось: модель читает путь
буквально, и если папка лежит под другим именем, она честно отвечает «эталона
нет» и отказывается работать.

### Проверки объявлены в задании

```yaml
acceptance:
  - id: S1
    kind: sql_no_plaintext_password
    glob: "**/*.py"
    weight: 25
  - id: A3
    kind: contains
    file: server.py
    any_of: ["pbkdf2_hmac", "bcrypt"]
    weight: 15
```

Вид проверки — это её `kind`; новый вид добавляется одной функцией в
`bench/checks.py`, а не правкой вызывающего кода. Полный список:
`zagent.bat bench kinds`.

Шаблоны поддерживают `**/` (ноль или больше папок), `*`, `?` и скобки
`{a,b}`. Скрытые папки вроде `.venv` в результат не попадают.

### Штрафы — за то, что не ловится проверками

Отсутствие файла можно проверить, а вот пароль в открытом виде внутри строки —
тоже, но «пароль не хешируется» нельзя доказать, не запустив код. Штрафы
покрывают то, что не имеет однозначного признака: подключённый CDN, оставшийся
`TODO`, подделка `User-Agent`.

### Как измеряется использование эталона

Не по упоминанию названия папки, а по сходству текста: `difflib` сравнивает
файлы эталона с файлами результата, берётся лучшая пара для каждого файла,
итог — взвешенное среднее по объёму. Замеры на живой модели:

| Что сделал агент | Сходство |
|---|---:|
| скопировал эталон, поправил тексты | 0.99 |
| переписал под свою задачу | 0.48–0.70 |
| прочитал и написал своё | 0.30–0.33 |

Порог 0.35 стоит между последними двумя группами. `autojunk` в `difflib`
обязательно выключен: он выбрасывает «частые» строки (`}`, `    return`), и на
повторяющемся файле даёт 0.002 вместо 0.874 — сходство падает не из-за
различий, а из-за алгоритма.

`reinvented_wheel` — это **метка для разбора**, а не приговор. Она означает одно
из трёх: агент не знает про библиотеку (правьте промпт), эталон плохо
индексирован (правьте `INDEX.yaml`), задача была нестандартной (метка врёт).

### `--dry`: почему без сети

Заглушка не пишет файлы с нуля — она копирует подложенный эталон с небольшой
правкой, то есть делает ровно то, что делал бы хороший агент. Зелёный прогон
значит, что проверки и веса настроены верно; красный на живом прогоне будет
виной агента, а не проверки. Это дешёвый способ отличить одно от другого.

### Метрики

```
reports/2026-10-05_2151/
├── ИТОГ.md        сводка по прогонам
├── МЕТРИКИ.md     доля успеха, доля использования эталонов, тренд
└── LANDING-001.md отчёт по заданию: проверки, штрафы, артефакты
```

Тренд сравнивает начало и конец окна из пяти прогонов. Пока данных меньше
десяти, тренд возвращает «недостаточно данных» — одна точка не показывает
динамику.

### Библиотека эталонов

`ref/INDEX.yaml` — единственный вход для агента. Правила пополнения
(`ref/README.md`): эталон меньше 500 строк, самодостаточен, у него есть
README с разделом «когда **не** применять», и он обязательно записан в индекс.

Сейчас семь эталонов: два лендинга, авторизация, парсер, OCR, змейка и
мета-папка с анти-паттернами.

### Дизайн-системы: 74 описания в стиле топовых брендов

`ref/awesome-design-md-main/design-md/` — по папке на бренд: `linear.app`,
`vercel`, `stripe`, `apple`, `nike`, `tesla`, `nvidia` и ещё 68. Внутри не код,
а описание: цвета, шрифты, шкала радиусов, сетка, компоненты и правила
«делай / не делай».

Это отдельный путь, а не эталон в обычном смысле: сравнивать описание с
результатом бессмысленно, поэтому в сходство оно не попадает.

Задание подключает стиль отдельной строкой:

```yaml
design: linear.app

ref_hint:
  primary: landing/templates/saas-minimal
```

Разделение намеренное: кодовый эталон отвечает «как устроен проект»,
дизайн-система — «как он должен выглядеть». Смешивать в одном списке нельзя,
иначе агент будет искать в папке с описаниями исполняемый код.

В промпт уходит выжимка (характер, палитра, шрифты, главные запреты) — 1200
символов вместо 40 КБ, — а полный `DESIGN.md` кладётся в песочницу. Выжимки
хватает, чтобы не гадать с цветом; сетка и радиусы берутся уже из файла.

Извлекается автоматически: палитра по hex, шрифты из раздела про семейство,
запреты из разделов Don't. Тон бренда (`DESIGN_TONES`) прописан вручную —
угадать его по папке нельзя.

```bash
zagent.bat bench refs        # посмотреть библиотеку
```

### Проверки выводятся из deliverables

Задание можно не писать руками:

```yaml
task_id: DESIGN-002
goal: Сверстай посадочную страницу…
deliverables: [index.html, style.css, script.js]
```

Стенд сам построит проверки: каждый файл должен существовать, HTML — быть
с `alt` у картинок, CSS — содержать медиазапросы и не быть пустым, Python —
компилироваться. Балл считается 40 — как у задания с ручными проверками.

Раньше `acceptance` был обязательным, и самое естественное задание нельзя
было даже запустить.

## Ограничения, которые важно знать

- **OpenRouter даёт 50 RPD** на аккаунт. На практике это главное ограничение
  проекта: 17 бесплатных моделей, но суммарно 50 запросов в сутки. Остальные
  шлюзы (Groq, Z.ai, Cloudflare, Mistral, llm7.io) без дневного потолка.
- **Codex умеет только Responses API.** `wire_api = "responses"` — единственное
  поддерживаемое значение, поэтому шлюзы без `/responses` (Cloudflare Workers AI,
  llm7.io, Gemini OpenAI-совместимый эндпоинт) в Codex не подключаются.
- **Zed не показывает OpenCode Free модели** — они разрешены только изнутри
  OpenCode.
- **Пинг одного шлюза идёт пачками с паузой** (`--pause`, по умолчанию 1.5 с).
  Лимиты считаются на аккаунт, поэтому 6 параллельных запросов к llm7.io
  (1 RPS анонимно) гарантированно дают 429.
- **Reasoning-модели** (gpt-oss, nemotron, glm-flash) при малом `max_tokens`
  возвращают пустой текст. Для пинга 256 токенов, для агента 4096 с повтором.
- **Бесплатные модели слабее в длинном контексте.** Агент дробит задачи на шаги
  и перечитывает файлы вместо того чтобы держать всю кодовую базу в промпте.
- **Не все бесплатные модели умеют вызывать инструменты.** На живом прогоне
  `groq/openai/gpt-oss-120b` ответил `Tool choice is none, but model called a
  tool`: модель решила вызвать инструмент, хотя вызов был запрещён. Такие модели
  годятся для консультации, но не для агента — стенд называет это в отчёте
  отдельно от лимита запросов, потому что лечится по-разному.
- **Стенд тратит токены на каждый прогон.** Перед серией изменений сначала
  `zagent.bat bench run all --dry`: он проверяет стенд бесплатно.
