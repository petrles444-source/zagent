# auth-flow

Регистрация, вход и сброс пароля на стандартной библиотеке: три страницы,
один `sqlite3`, ноль зависимостей.

## Когда применять

- Нужна связка «регистрация + вход + сброс пароля» без Flask и без сборки.
- Учебный проект: показать, как выглядит пароль, который нельзя украсть из
  таблицы.
- Нужна база, которая переживает перезапуск сервера: сессии лежат в базе, а
  не в памяти.

## Когда НЕ применять

- Нужен OAuth, «Войти через GitHub» → этот файл про пароли, не про протоколы.
- Нужен админ, роли, приглашения → здесь одна роль и одна таблица.
- Нужны ORM и миграции → здесь голый `sqlite3` и `CREATE TABLE IF NOT EXISTS`.
- Нужно обслуживание тысяч пользователей → сессии в базе на каждый запрос.

## Запуск

```
python server.py          # → http://127.0.0.1:8765
PORT=9000 python server.py
```

База создаётся сама рядом с файлом: `auth.sqlite3`.

## Правила безопасности, которые здесь соблюдены

| Правило | Как сделано |
|---|---|
| Пароль не хранится | `pbkdf2_hmac` со случайной солью, 240 000 итераций |
| Сравнение за постоянное время | `hmac.compare_digest`, а не `==` |
| Счётчик итераций в базе | `pw_iters` — можно пересчитать хеши позже |
| Сессия в cookie, а не в JS | `HttpOnly; SameSite=Lax; Path=/` |
| Сессия не переживает смену пароля | `DELETE FROM sessions` в сбросе |
| Токен сброса одноразовый | строка удаляется сразу после использования |
| В базу кладётся хеш токена | сам токен живёт только в ссылке |
| Срок жизни токена | 30 минут, проверяется при использовании |
| Нет ответа «такого адреса нет» | один текст на «нет адреса» и «неверный пароль» |
| Нет утечки по времени ответа | при «нет адреса» пароль всё равно считается |
| Нет вставки пользователя из строки | только параметризованные запросы |

## Почему ответы на вход одинаковые

Если «неверный пароль» и «нет такого адреса» дают разный текст, форма входа
превращается в справочник: перебором адресов можно выяснить, кто зарегистрирован.
Поэтому `_login` при отсутствии адреса всё равно считает хеш — иначе время
ответа выдаёт, существует ли аккаунт.

## Чего здесь нет намеренно

- **Нет ограничения попыток входа.** В бою нужен счётчик: 5 попыток в минуту на
  адрес. Учебный образец сознательно оставляет это за рамками.
- **Нет `Secure` у cookie.** Флаг добавляется только под HTTPS: с `http://`
  браузер его проигнорирует, а пример должен работать и по `http://127.0.0.1`.
- **Нет подтверждения почты.** Регистрация считается настоящей сразу.
- **Нет удаления аккаунта и смены почты.**
- **Нет `hashlib.scrypt`.** PBKDF2 доступен везде и достаточно широк;
  `scrypt` лучше, но требует OpenSSL с его поддержкой.

## Если адаптируешь

Не выбрасывай `hmac.compare_digest`, одинаковые ответы и удаление сессий при
смене пароля. Это те три места, где чаще всего появляется дыра, а код выглядит
совершенно обычно.
