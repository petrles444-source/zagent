# waitlist — только сбор почты

Одна страница, одно поле, без кнопок-приманок. Случай, когда «лендинг» — это
перебор.

## Когда применять

- Нужен только сбор адресов: страница-заглушка до запуска.
- Ещё не решено, какой продукт, но собрать надо.
- Нужно проверить, есть ли спрос, до того как делать лендинг.
- Хочется один файл, который можно отправить хостами без настроек.

## Когда НЕ применять

- Нужен раздел с преимуществами или FAQ → `saas-minimal`.
- Нужна авторизация → `multipage/auth-flow`.
- Нужно собрать не только почту, но и пожелания к продукту → добавь
  `<textarea>` и вторую проверку в `script.js`.

## Что внутри

| Файл | Зачем |
|---|---|
| `index.html` | страница и форма в одном файле |
| `style.css` | минимальные стили, тёмная тема по системе |
| `script.js` | проверка и отправка |

## Отличия от `saas-minimal`

- **Всё в одном файле** против трёх. Для страницы в два экрана делить на
  файлы незачем.
- Нет меню, таблицы цен, блока преимуществ.
- Обязательное поле только одно. Чем меньше полей, тем выше конверсия.

## Приёмы, которые стоит перенести

1. **Ошибка под полем, а не сверху.** Пользователь не должен искать, что
   не так.
2. **`autocomplete="email"`** — браузер подставит адрес сам.
3. **Кнопка блокируется на время отправки** — иначе получишь три одинаковых
   заявки от одного человека.

## Чего здесь нет намеренно

Заглушки `/api/lead`: она вернёт ошибку, и форма об этом сообщит. Это лучше,
чем молчаливая потеря заявки.
