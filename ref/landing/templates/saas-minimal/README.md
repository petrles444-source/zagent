# saas-minimal

Одностраничник без сборки: hero, преимущества, цены, форма заявки.

## Когда применять

- Нужен лендинг или витрина продукта на статике.
- Открыл `index.html` — и работает, без `npm`, без сборщика.
- Форма заявки отправляется на один адрес методом POST.
- Никаких аккаунтов, ролей и роутинга.

## Когда НЕ применять

- Нужна авторизация → `multipage/auth-flow`.
- Нужна админка или просмотр заявок → это отдельное приложение, не лендинг.
- Нужен раздел блога с тегами и поиском → собирай из компонентов, здесь
  только три статичных блока.
- Нужен биллинг с оплатой картой → здесь кнопка без интеграции.

## Что внутри

| Файл | Зачем |
|---|---|
| `index.html` | разметка; форма с `novalidate` — валидация в скрипте |
| `style.css` | токены, тёмная тема по системе, адаптив 480/768 |
| `script.js` | проверка почты, отправка, обработка ошибок |

## Приёмы, которые стоит перенести

1. **Цвета только токенами.** `:root` задаёт переменные, `:root` же переключает
   их по `prefers-color-scheme`. Ни одного цвета в правиле — тему можно менять
   без правок разметки.
2. **`focus-visible`, а не `outline: none`.** Доступность не должна ломаться
   вместе с дизайном.
3. **`aria-invalid` + `role="alert"`.** Сообщение об ошибке читается
   скринридером, а не только визуально.
4. **Место под сообщение зарезервировано** `.err { min-height }` — текст ошибки
   не сдвигает кнопку при появлении.
5. **`autocomplete="email"`** — браузер подставляет адрес сам.
6. **`prefers-reduced-motion`** — выключает анимации, если человек их отключил.

## Чего здесь нет намеренно

- Бэкенда: `POST /api/lead` в заглушке вернёт ошибку, и форма честно об этом
  скажет.
- Фреймворка: чтобы скопированный файл не тянул зависимости.
- Иконок и картинок: `<img alt="пример">` — только чтобы был смысл проверять
  атрибут.

## Если адаптируешь

Меняй тексты, цвета и блоки. Не выбрасывай `:focus-visible`, `aria-invalid` и
`prefers-reduced-motion` — они и отличают рабочий шаблон от набора стилей.
